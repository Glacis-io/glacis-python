Receipts you typed into a form are a demo. Receipts your system emits are
evidence. This section is the shortest path from one to the other.

```bash
pip install glacis
```

`glacis` 0.8.0, Python 3.9+. Three runtime dependencies (`httpx`, `pydantic`,
`pynacl`); provider SDKs are optional extras.

## Pick a path

<Tabs>
  <TabItem label="Wrap your provider">

Swap your provider's constructor for the attested one. Nothing else in your code
changes, and the wrapper attempts a receipt on every wrapped call — **best
effort, never blocking**: if attestation or storage fails, the exception is
swallowed by design and you still get the model response, with no receipt. See
[what "best effort" costs you](#attestation-is-best-effort-never-a-gate) below.

```python
import os
from glacis.integrations.openai import attested_openai, get_last_receipt

client = attested_openai(
    openai_api_key=os.environ["OPENAI_API_KEY"],
    offline=True,
    signing_seed=bytes.fromhex(os.environ["GLACIS_SIGNING_SEED"]),
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello!"}],
)

receipt = get_last_receipt()
```

  </TabItem>
  <TabItem label="Config-first">

Put mode, service identity, controls, sampling and storage in a `glacis.yaml`
next to your app. The only Python is the factory call, which reads the file.

```yaml
# glacis.yaml
version: "1.3"
attestation:
  offline: true
  service_id: "claims-triage"
sampling:
  l1_rate: 0.1
controls:
  input:
    pii_phi:
      enabled: true
      if_detected: "flag"
evidence_storage:
  backend: "sqlite"
```

```python
import os
from glacis.integrations.litellm import attested_litellm

seed = bytes.fromhex(os.environ["GLACIS_SIGNING_SEED"])  # 64 hex chars

client = attested_litellm(config="glacis.yaml", signing_seed=seed)
```

`attestation.offline: true` in the YAML means the factory needs a seed: without
one it raises `ValueError: signing_seed is required for offline mode`. The
config file cannot supply it — a signing key does not belong in a file you
commit.

  </TabItem>
  <TabItem label="Attest directly">

For anything that is not a chat completion — an embedding job, a retrieval step,
a human review, a batch decision — call `attest()` yourself.

```python
import os
from glacis import Glacis

glacis = Glacis(mode="offline", signing_seed=os.urandom(32))

receipt = glacis.attest(
    service_id="claims-triage",
    operation_type="classification",
    input={"claim_id": "C-1029", "text": "..."},
    output={"decision": "escalate", "score": 0.82},
)
```

## Attestation is best effort, never a gate

The wrapper path is deliberately fail-open. `attest_and_store()` in
`glacis/integrations/base.py` wraps the whole attestation-and-storage step in a
`try` and catches **every** exception, printing only when `debug=True`:

- Your provider call is made and its response is returned regardless. GLACIS
  never blocks, delays or fails an LLM call because attestation had a problem.
- If attestation fails, no receipt exists for that call. `get_last_receipt()`
  then returns `None` — or, worse to read past, the **previous** call's receipt
  from the same context.
- Nothing anywhere retries, and nothing surfaces the failure to your code.

So the accurate sentence is *the wrapper attempts a receipt on every wrapped
call*, not *every call is attested*. If a missing receipt matters to you, check
that `get_last_receipt()` returned one and that its `id` is not one you have
already seen, and run with `debug=True` while you are diagnosing.

The one place the wrapper *does* raise is a blocking control:
`GlacisBlockedError` stops the provider call before it is made. That is a
policy decision you configured, not an attestation failure.

## Decide one thing first: offline or online

This is the decision that changes what your receipts are worth to somebody else.

| | Offline <ReceiptBadge kind="self-signed" /> | Online |
| --- | --- | --- |
| Needs | A 32-byte signing seed you keep | A workspace key (`glsk_…`) |
| Network | None. Nothing leaves the process. | Hash + metadata to `api.glacis.io` |
| Signed by | You | The GLACIS service, with its key |
| `witness_status` on the returned object | `"UNVERIFIED"` | `"WITNESSED"` — a **mode label**, not a proof |
| Second signature or inclusion proof | None | Not exposed on the returned object |
| Worth to a third party | It is your diary | A record signed by someone other than you |

Start offline — it works this second, with no account. Move to online when
somebody outside your organisation needs a signer who is not you.
[Offline vs online](/connect/offline-vs-witnessed/) is the long version, and it
is worth reading before you put a <ReceiptBadge kind="witnessed" /> badge on
anything: at 0.8.0 that tier comes from the portal's mint path, not from an SDK
`witness_status` string.

<Aside type="caution" title="What never leaves your process">
  `attest()` hashes `{"input": …, "output": …}` with canonical JSON and SHA-256,
  and sends **only the hash**. Prompts, completions, documents and patient data
  are not transmitted in either mode. Your provider API keys are never sent to
  GLACIS either. The exact canonicalisation, and where it diverges from RFC
  8785, is written out in
  [Quickstart](/connect/quickstart/#the-canonicalisation-actually-used).
</Aside>

## Get a workspace key

Online mode needs a key. Create a workspace at
[app.glacis.dev](https://app.glacis.dev), open workspace settings, and mint one:

- `glsk_test_…` for development
- `glsk_live_…` for production

The key is shown once. Store it in your secrets manager; pass it as
`api_key=` / `glacis_api_key=` or read it from the environment.

<Aside type="note" title="Offline needs none of this">
  Key minting and the hosted witness ship with the launch build of
  app.glacis.dev. Everything on the offline path — `pip install glacis`, local
  Ed25519 signing, the provider wrappers with `offline=True`, the whole of
  [Verify from Python](/verify/cli/) — works today with no account at all.
  Build against offline first; the switch to online is one constructor
  argument.
</Aside>
