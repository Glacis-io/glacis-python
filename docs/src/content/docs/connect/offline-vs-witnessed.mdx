## The diary problem

Keep a diary. Write in it every day, in ink, and never tear a page out. It is a
genuine record — you can prove to yourself nothing was altered, because you would
notice.

Now hand it to somebody who suspects you of something. They have one question
you cannot answer: *what stops you from having written all of this last night?*

Closing that question needs a **countersignature from a party that is not you**,
and ideally an append-only log the record was entered into. A signature — any
signature, including a very good one — proves only *the bytes have not changed
since they were signed*. It says nothing about **when** they were signed or
**who else knew**.

Hold that framing while reading the rest of this page, because the SDK's two
modes are *transport* modes. Which artifact you end up with, and what it proves,
is set out precisely below.

## The two modes at 0.8.0

### Offline

<ReceiptBadge kind="self-signed" gloss />

```python
glacis = Glacis(mode="offline", signing_seed=seed)
```

- Requires a 32-byte Ed25519 seed you generate and keep.
- Makes **no network calls at all**. Works air-gapped.
- Signs locally, stores locally (`~/.glacis/glacis.db` by default).
- `attestation.id` starts `oatt_`; `attestation.witness_status == "UNVERIFIED"`.
- Free, forever, and not a trial of anything. It never involves us.

What you hold afterwards is a record signed by **one key: yours**. That is a
diary, and the docs call it <ReceiptBadge kind="self-signed" /> everywhere.

Good for: local development, CI, air-gapped estates, internal record-keeping,
and any case where the reader of the receipt already trusts the writer.

Not good for: handing to a customer, an auditor, an insurer or a regulator as
proof of what happened. They are being asked to trust your clock.

### Online

```python
glacis = Glacis(api_key=os.environ["GLACIS_API_KEY"])
```

- Requires a workspace key (`glsk_test_…` / `glsk_live_…`) from
  [app.glacis.dev](https://app.glacis.dev).
- Sends the **hash and metadata** to `api.glacis.io` — never the payload.
- The server signs and returns an attestation; the SDK returns whatever the
  server sent, with `is_offline=False`.
- `attestation.witness_status == "WITNESSED"`.

<Aside type="caution" title="witness_status = WITNESSED is a mode label, not a proof">
  In `glacis` 0.8.0 `witness_status` is a **computed property with one input**:

  ```python
  # glacis/models.py
  @property
  def witness_status(self) -> str:
      return "UNVERIFIED" if self.is_offline else "WITNESSED"
  ```

  It reports which *mode* produced the object. It does not look at a
  countersignature, an inclusion proof, a tree head or a second key, because
  the returned `Attestation` has nowhere to put one: the model carries exactly
  one `public_key` and one `signature`. The SDK's response normaliser
  (`_normalize_server_response`) keeps a fixed list of fields and drops
  everything else, so even a server response containing a transparency proof
  would not survive into the object you get back.

  Reading `"WITNESSED"` off an SDK object therefore tells you *this went through
  the online path*. On its own it is not grounds for showing anyone a
  <ReceiptBadge kind="witnessed" /> badge.
</Aside>

## What online mode actually returns today

Verified against `glacis` 0.8.0 in this repository:

| | Offline `attest()` | Online `attest()` |
| --- | --- | --- |
| Who signs | You, locally, from your seed | The server, with its key |
| Keys on the returned object | One (yours) | One (the server's) |
| Countersignature by a second party | None | Not exposed on the returned object |
| Inclusion proof / tree head | None | Not exposed on the returned object |
| `witness_status` | `"UNVERIFIED"` | `"WITNESSED"` (mode label) |
| Independently checkable timestamp | No | Not from this object alone |

So the honest reading of an online attestation at 0.8.0 is: **a record signed by
a party other than you** — the GLACIS service — rather than a record you signed
yourself. That is a real step up from a diary, because the signer is not the
author. It is not yet the full witnessed artifact, because the object does not
carry the proof that lets a *third* party check inclusion and time without
asking the same server again.

`Glacis.verify(attestation_id)` fetches `GET /v1/verify/{id}` and can return a
`proof` and a `tree_head` alongside the verdict — but that is the server
answering a question about its own record, and the SDK does not recompute the
Merkle path locally. There is no Merkle verification code in the package.

## Where the witnessed badge comes from

<ReceiptBadge kind="witnessed" gloss />

The <ReceiptBadge kind="witnessed" /> tier means a party that did not author the
record countersigned it and entered it in an append-only log, and that the
reader can check both without trusting the author.

The `glacis` SDK does not produce that artifact at 0.8.0 — neither mode returns
a second signature or an inclusion proof. What adds it is the **portal's mint
path in the launch build**: mint a receipt at
[app.glacis.dev](https://app.glacis.dev) and the hosted witness's own response —
receipt plus its inclusion envelope, signed tree head included — is what you get
back and what the permalink carries. The portal shows WITNESSED only when the
log reports the entry as included *with* a proof and a signed tree head, and an
explicit awaiting-inclusion state otherwise.

Two caveats worth carrying:

- **Independence is a deployment property, not a format property.** A
  countersignature is only worth what the countersigner's independence from the
  operator is worth. Ask who runs the witness before treating a badge as
  third-party evidence.
- **A witnessed artifact is not an SDK object.** If you want one today, mint it
  in the portal. Do not synthesise one from an online `attest()` response.

<Aside type="caution" title="Do not upgrade a badge on your own say-so">
  If you are building a UI over SDK output: render <ReceiptBadge kind="self-signed" />
  for offline attestations, and for online ones render what you actually
  verified. `witness_status == "WITNESSED"` is not that verification. Showing a
  green witnessed badge because a string said `WITNESSED` is exactly the
  conflation these docs exist to prevent.
</Aside>

<Aside type="caution" title="Neither mode makes anything compliant">
  Every tier here produces evidence *that a claim was generated* — not a finding
  that the claim is true, not an audit, not a certification. See
  [what a check proves](/verify/what-a-check-proves/).
</Aside>

## What is actually sent

Offline sends nothing. Online sends exactly this request body to
`POST /v1/attest` (`glacis/client.py`), plus the key in a header:

| | Transmitted in online mode? |
| --- | --- |
| Whatever you passed as `input=` | No — SHA-256 only |
| Whatever you passed as `output=` | No — SHA-256 only |
| Your provider API keys | No |
| Your GLACIS key | Yes — as the `X-Glacis-Key` request header |
| `service_id`, `operation_type` | Yes |
| `evidence_hash` | Yes |
| `cpr_hash` | Yes, when control-plane results were attached |
| `control_plane_results` | Yes, **verbatim**, when you attach them — see below |
| `operation_id`, `operation_sequence`, `supersedes` | Yes, when set |

**There is no timestamp in the request body.** The online attestation's
timestamp is whatever the server returns. (An earlier version of this page
listed a timestamp row; the SDK never sent one.)

<Aside type="danger" title="control_plane_results is transmitted as you supplied it">
  The rows above say "prompts and documents are not transmitted" about `input=`
  and `output=`, which are hashed. `control_plane_results` is **not** hashed on
  the way out. `_attest_online` puts it into the request body unchanged:

  ```python
  if control_plane_results:
      body["control_plane_results"] = control_plane_results
  ```

  It is typed `Optional[dict[str, Any]]` — an arbitrary dictionary. Nothing in
  the SDK inspects it, redacts it, truncates it or checks it for anything.
  `cpr_hash` is sent *alongside* it, not instead of it.

  So: **anything you put in `control_plane_results` leaves your machine in
  online mode, including PHI, prompt text or a whole document if you put one
  there.** A probe confirmed raw patient-shaped fields arriving in the request
  body untouched.

  This is not hypothetical for anyone building their own control plane. The
  wrapper-built structure is safe by construction — it carries policy id and
  version, environment, tags, model id and provider, the **hash** of the system
  prompt, the temperature, and per-control id/type/version/provider/latency/
  status/score/`result_hash` — no prompt or completion text. But that safety is
  a property of what the wrapper puts there, not of the field. If you build the
  dictionary yourself, you own that boundary.

  Offline mode transmits nothing at all, so none of this applies to it.
</Aside>

## What is retained locally

This differs by mode *and* by how you call the SDK, so it is worth being exact:

| Call path | Written to disk | Also on the returned object |
| --- | --- | --- |
| `attest()`, offline | The receipt row, plus a **100-character preview** of `str(input)` and `str(output)` — not the full payload. Signed `control_plane_results` is stored whole (0.8.1; see below) | — |
| `attest()`, online | **Nothing.** The online path never writes to the local receipt store | Your **raw** `input` and `output`, in memory, whenever the server assigns L1 or L2 |
| Provider wrappers (`attested_openai` and friends), either mode | A **projection** of the request and response, via `store_evidence()` into the `evidence` table — not everything the provider saw | Same L1/L2 rule in online mode |

Three corrections to the version of this table that said "nothing" and "the
complete request and response":

**Online `attest()` writes nothing to disk, but it can hand you back your own
payload.** When the server's response carries a `sampling_decision` of `L1` or
`L2`, `_attest_online` attaches the raw values you passed to
`attestation.evidence.data` as `{"input": …, "output": …}`
(`glacis/client.py`). Nothing is written, but the object you are holding now
contains the prompt and the completion in full.

<Aside type="caution" title="Serialising an online receipt can serialise your prompt">
  [Quickstart](/connect/quickstart/) shows `json.dump(receipt.model_dump(), …)`,
  and `/verify/` shows sharing a receipt as a `#r=` link. For an offline receipt
  those are safe: `evidence` is never populated. For an **online L1/L2** receipt
  the dump contains `evidence.data.input` and `evidence.data.output` — the whole
  exchange. Check `receipt.evidence is None` before you write a receipt to a
  file you intend to send anywhere, or drop the field:
  `receipt.model_dump(exclude={"evidence", "review"})`.
</Aside>

**The wrappers store a projection, not the exchange.** Each wrapper builds its
own `input_data` / `output_data` dictionaries and stores those. For
`attested_openai` (`glacis/integrations/openai.py`) that is exactly:

| Stored | Not stored |
| --- | --- |
| `model`, `messages` | Every other keyword you passed — `temperature`, `top_p`, `max_tokens`, `tools`, `tool_choice`, `response_format`, `seed`, `stop`, `n`, `user`… |
| Response `model`; per choice `message.role`, `message.content`, `finish_reason`; `usage` as `prompt_tokens` / `completion_tokens` / `total_tokens` | Response `id`, `created`, `object`, `system_fingerprint`, `service_tier`, choice `index` and `logprobs`, `message.tool_calls`, `message.refusal`, and the token-detail breakdowns |

The other wrappers project differently — Anthropic adds a `system` key and keeps
`content` blocks, `stop_reason` and its own token counts; Gemini keeps
`system_instruction` and `candidates` — but every one of them is a projection.
**A tool call your model made is not in your evidence.**

**And the receipt commits to the projection, not to the exchange.** The wrapper
passes those same dictionaries to `attest()`, so `evidence_hash` is computed
over the projection. To prove later that a receipt refers to a particular call,
you have to rebuild the same projection — recomputing over the provider's raw
JSON will not reproduce the hash. See
[Sampling and evidence](/reference/sampling-and-evidence/).

If you call `attest()` directly and want to prove the hash binding later, retain
the input and output yourself: offline keeps 100 characters for orientation, and
online keeps nothing on disk.

<Aside type="caution" title="Offline storage lost signed content up to 0.8.0">
  `control_plane_results` is *inside* the offline signature. Up to and including
  0.8.0 — the version `pip install glacis` gives you today — neither storage
  backend wrote it. A receipt reloaded with `get_last_receipt()` or
  `get_receipt()` came back without the content its own signature covered, so a
  third party could not verify it, and `Glacis.verify()` did not notice because
  it never checks a signature.

  Fixed in this repository and staged as 0.8.1, **not published**: both backends
  now persist and reconstruct the field. Rows already written cannot be repaired
  — the content was never stored. Reading one of them gives you an attestation
  with `cpr_recovery_error` set, naming the loss, and `verify()` fails closed
  with that reason rather than pretending the receipt had no control-plane
  results. If you attached control-plane results under 0.8.0 and relied on the
  local store as your copy of record, treat those receipts as unverifiable by
  anyone else.
</Aside>

## Moving between them

The `attest()` call does not change. Only the constructor does:

```python
import os
from glacis import Glacis


def make_client():
    key = os.environ.get("GLACIS_API_KEY")
    if key:
        return Glacis(api_key=key)
    return Glacis(
        mode="offline",
        signing_seed=bytes.fromhex(os.environ["GLACIS_SIGNING_SEED"]),
    )
```

The provider wrappers take the same decision through `offline=` /
`glacis_api_key=`, or from `attestation.offline` in
[`glacis.yaml`](/connect/configuration/).

<Aside type="note" title="Receipts do not retroactively become witnessed">
  There is no upgrade path for an existing offline receipt. Witnessing has to
  happen at the moment of attestation, because the value of it is that the time
  was not yours to choose. Receipts you signed offline last month stay
  self-signed.
</Aside>

## Constructor rules, exactly

Verified against 0.8.0:

| Call | Result |
| --- | --- |
| `Glacis()` | `ValueError: api_key is required for online mode` |
| `Glacis(mode="offline")` | `ValueError: signing_seed is required for offline mode` |
| `Glacis(mode="offline", signing_seed=os.urandom(16))` | `ValueError: signing_seed must be exactly 32 bytes` |
| `Glacis(api_key="glsk_live_…")` | Online mode |
| `Glacis(mode="offline", signing_seed=<32 bytes>)` | Offline mode |

The SDK fails loudly on a missing key rather than silently downgrading to
offline. A silent downgrade would hand you a pile of self-signed receipts you
believed were witnessed, which is the worst outcome available.
