Glacis is **runtime guardrails for AI**. Covered decisions are held to the bounds you set while the action is live, and each covered decision leaves a **signed record** someone else can check — without taking custody of your content. The open format for that record is [OVERT](https://overt.is).

<Aside type="note" title="Record vs receipt">
  On these docs and on glacis.io, the human-facing word is **record**. The OVERT specification and some SDK field names still say *receipt* — same artifact, different audience.
</Aside>

## The smallest useful example

Works right now, with no account, no key, and no network:

```python
import os
from glacis import Glacis

glacis = Glacis(mode="offline", signing_seed=os.urandom(32))

receipt = glacis.attest(
    service_id="claims-triage",
    operation_type="inference",
    input={"prompt": "..."},    # hashed locally, never transmitted
    output={"response": "..."}, # hashed locally, never transmitted
)

print(receipt.id)              # oatt_...
print(receipt.witness_status)  # UNVERIFIED
```

Offline SDK records are **self-signed** operator statements. They are checkable
as SDK artifacts; they are **not** claimed as conforming OVERT documents. See
[OVERT](/overt/) and [offline vs online](/connect/offline-vs-witnessed/).

## What is transmitted

| | Leaves your environment? |
| --- | --- |
| Your prompts | No — SHA-256 hash only |
| Model outputs | No — SHA-256 hash only |
| Your provider API keys | No |
| `service_id`, `operation_type` | Yes, in online mode |
| `evidence_hash`, `cpr_hash` | Yes, in online mode |

In offline mode, nothing is transmitted at all. Online / witnessed mode is not
generally available yet — do not plan production on it.

## And one flag that cuts across both

<ReceiptBadge kind="sample" gloss />

SAMPLE is about the *subject matter*, not the cryptography: the operation it
describes never ran. A green check on a sample establishes that the bytes are
unedited — nothing about an event.

<Aside type="caution" title="What a record is not">
  A signed record is **cryptographic evidence that the claims stated in it were
  generated** for a given event. It is not a compliance certificate, not an
  audit result, not a guarantee that a control was effective, and not a
  statement that the model was right. Nothing here makes a system compliant,
  certified, EU AI Act–ready, ISO-certified, or SOC-attested.
  [What a check proves](/verify/what-a-check-proves/) draws the line precisely.
</Aside>
