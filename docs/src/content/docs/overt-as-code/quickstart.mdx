## Intended flow

1. Author a policy file (TOML) describing tools, data bounds, and enforcement mode.
2. Validate in CI before merge.
3. Activate the compiled policy on a [runtime](/runtime/) path that emits signed
   records for covered decisions.
4. Verify records with [Verify](/verify/) — knowing what a check does and does not prove.

## What success looks like

- Policy changes are reviewed like code.
- Invalid policy fails the build.
- Runtime status distinguishes enforced vs declared-not-enforced.
- Auditors receive records + exports, not screenshots alone.
