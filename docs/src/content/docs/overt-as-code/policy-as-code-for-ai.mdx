General-purpose policy engines decide authorization for APIs and infrastructure.
AI runtime governance adds requirements those engines were not designed to own
alone:

- **Content-safe evidence** — hashes instead of prompts/outputs.
- **Mediated-scope honesty** — records silent about un-mediated paths.
- **Control status vocabulary** — enforced / recorded / declared-not-enforced.
- **Standard portability** — [OVERT](/overt/) so verifiers are not vendor-captive.

OVERT-as-Code targets that wedge: AI-governance-shaped policy that compiles
toward runtime enforcement and checkable records. It is not "OPA but for AI" as
a slogan — and it is not GA.
