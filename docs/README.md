# GLACIS documentation portal

Source for [docs.glacis.io](https://docs.glacis.io). Astro + Starlight, deployed
to Cloudflare Pages.

## Information architecture

The site follows the activation ladder — a reader should be able to enter at the
rung that matches how much effort they are willing to spend right now:

| Section | Audience | Effort |
| --- | --- | --- |
| `start/` | Never seen a receipt. On a phone, possibly. | Browser only, ~2 min |
| `connect/` | Wants receipts out of their own system. | `pip install`, ~10 min |
| `verify/` | Was handed a receipt and has to judge it. | None |
| `overt.mdx` | Wants the open standard, not the product. | — |
| `reference/` | Already building; needs the exact surface. | — |

Old `/sdk/python/*` URLs are **redirected**, not deleted — they are linked from
PyPI package metadata and from the wild. The redirect map lives in
`astro.config.mjs`. If you move a page, add a redirect.

## Editorial rules

These are not style preferences. They are the reason the docs are worth reading.

1. **Never write "compliant", "protected" or "certified" as a claim.** A receipt
   is evidence that a claim was generated. Not a certificate, not an audit, not
   a finding of compliance. The words may appear only in a negation.
2. **SAMPLE / SELF-SIGNED / WITNESSED are always distinguished**, visually and
   in words, using `src/components/ReceiptBadge.astro`. A self-signed receipt is
   not a cheap witnessed receipt; it is a different claim. Never blur them.
3. **Every snippet is either verified or marked untested.** Prefer verified.
   See below.
4. **Unverifiable claims get cut, not hedged.** If we cannot demonstrate it
   against the published SDK or a live surface, it does not go on the page.
   Where the SDK does less than a reader would assume — offline `verify()` not
   checking signatures, wrapper attestation being fail-open — say so plainly and
   pin it with a check.
5. **Screenshots that do not exist yet use `Screenshot.astro`**, which renders an
   obvious placeholder. Never a mock-up presented as a capture.

## Verifying the snippets

```bash
pip install -e ..          # the SDK from this repo
pip install pyyaml         # for the glacis.yaml checks
python scripts/verify-doc-snippets.py
```

Every offline-mode behaviour these docs assert has a check in that script,
including the ones that are unflattering. It exits non-zero when a page has
gone out of date with the SDK. It cannot exercise witnessed mode or the provider
wrappers end to end — those need live keys, and the pages that describe them say
so.

## Development

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # must pass before committing
npm run preview
```

Adding a page: create the `.mdx` under the right section with `title` and
`description` frontmatter and a `sidebar.order`. `start/`, `connect/` and
`verify/` are autogenerated into the sidebar from the directory; `reference/` is
listed explicitly in `astro.config.mjs`.

## Layout

```
docs/
├── astro.config.mjs              # IA, sidebar, redirect map
├── scripts/
│   └── verify-doc-snippets.py    # executable proof the code on the pages runs
└── src/
    ├── components/
    │   ├── ReceiptBadge.astro    # SAMPLE / SELF-SIGNED / WITNESSED
    │   └── Screenshot.astro      # honest placeholder for pending captures
    ├── content/docs/
    │   ├── index.mdx
    │   ├── overt.mdx
    │   ├── start/
    │   ├── connect/
    │   ├── verify/
    │   └── reference/
    └── styles/custom.css
```

`REBUILD-NOTES.md` records what happened to every page in the 2026-08-08
rebuild and why.
